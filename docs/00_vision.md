# Назначение проекта

### Цель
Какую проблему решает проект?
- Позволяет создать персонажа для разных систем в одном месте
- Имеет локализацию на русском и английском языках с возможностью быстрого переключения между ними
- Поддержка хоумбрю правил
- Возможность добавления внешнего контента без изменения ядра

Для кого предназначен проект?
- Игроки, желающие попробовать разные системы
- Мастера, желающие делиться своим хоумбрю

Какая главная ценность проекта?
- Универсальность и доступность

Чем он отличается от существующих решений?
- Имеет русскую локализацию с легким доступом к оригинальному тексту правил для сверки

Почему пользователь должен выбрать именно его?
- Количество контента, которое пополняется силами комьюнити
- Понятный интерфейс, не требующий опыта взаимодействия с приборной панелью самолета
- Гибкость в создании персонажа

---
### Границы проекта
Что входит в MVP?
- Базовый конструктор персонажей, поддерживающий 2 контрастные системы - GURPS 4e, D&D 5e
  - Генерация классических листов персонажей с подставленными данными
  - Возможность экспорта листа для печати
  - Позволяет сохранять разные версии и состояния персонажа с возможностью легкого переключения между ними
- Список инструментов для создания персонажа с учетом разных источников (официальные книги, ХБ)
- Личный кабинет пользователя с хранимыми там персонажами

Что точно не войдет в первую версию?
- Поддержка создания своих ХБ
- Возможность делиться с другими пользователями

Какие функции могут появиться позже?
- Интеграция с другими сервисами
- Комнаты приключений
- Публичная библиотека контента
- Броски кубов
- Мобильное приложение

Какие идеи сознательно исключаются?
- Чаты и другие формы связи между пользователями внутри приложения
- Онлайн-бои
- Карты локаций
- Доска мастера

---
### Принципы системы

- Ядро не знает о конкретных НРИ
- Система не хранит “классы”, “расы” или “уровни” как обязательные сущности
- Все игровые механики описываются через универсальные сущности (контент + правила)
- Любая игровая система должна быть выражаема без изменения кода ядра
- Персонаж является результатом применения правил, а не фиксированной структурой

---
### Развитие
Как выглядит успешный проект через год?
Проект становится:
- инструментом для создания персонажей;
- системой для домашних правил;
- удобным листом персонажа;
- платформой для пары систем (D&D, PF2, maybe GURPS);
- локальным/нишевым стандартом.

Через три года?
- 3–6 поддерживаемых систем;
- стабильный rule engine;
- нормальный UI;
- небольшое, но активное комьюнити;
- кастомный контент (homebrew) — ключевая фича;

# Возможные целевые состояния проекта
### Минимальный успех
- поддержка 2–3 систем (D&D, PF2, GURPS);
- стабильный движок правил;
- удобный лист персонажа;
- поддержка домашнего контента.
### Расширенный успех
- пользовательские системы;
- библиотека контента;
- обмен homebrew;
- API.
### Запрещённые направления роста
- превращение в VTT;
- попытка заменить Roll20/Foundry;
- переход в “игровую платформу”;
- добавление real-time мультиплеера;
- уход в “всё про игры вообще”.
