# Интерфейс

Интерфейс должен помогать пользователю работать с игровой системой, а не требовать знания её внутреннего устройства.

Основной принцип — минимальное количество действий для выполнения наиболее частых задач.

---

# Пользователь

## Путь нового пользователя

Новый пользователь должен иметь возможность:

1. выбрать игровую систему;
2. создать нового персонажа;
3. заполнить основные характеристики;
4. выбрать доступный контент;
5. сохранить персонажа.

Для выполнения этих действий не должно требоваться предварительное изучение документации.

## Частые действия

Наиболее частыми являются:

- создание персонажа;
- изменение характеристик;
- выбор способностей;
- поиск контента;
- просмотр итоговых параметров;
- сохранение изменений.

Интерфейс должен быть оптимизирован именно под эти сценарии.

## Что должно быть доступно в один клик?

Без перехода между несколькими экранами должны быть доступны:

- сохранение персонажа;
- отмена последнего изменения;
- поиск контента;
- просмотр итоговых характеристик;
- переход к ошибкам и предупреждениям;
- история изменений.

---

# Персонаж

## Как отображать карточку?

Карточка персонажа должна содержать:

- основные сведения;
- характеристики;
- навыки;
- особенности;
- экипировку;
- производные параметры;
- список активных эффектов.

Структура должна адаптироваться под конкретную игровую систему.

## Как отображать ошибки правил?

Ошибки должны:

- объяснять причину;
- указывать источник;
- показывать связанные объекты;
- предлагать возможный способ исправления, если это возможно.

Ошибки не должны ограничиваться сообщением "что-то пошло не так".

## Как показывать зависимости?

Пользователь должен понимать, почему получено конкретное значение.

Для вычисляемых параметров должна быть возможность просмотреть:

- какие правила были применены;
- какие объекты повлияли на результат;
- какие эффекты были использованы.

Такое отображение может быть представлено в виде списка, дерева или графа.

## Как отображать изменения после выбора новой способности?

После любого изменения интерфейс должен явно показывать:

- какие характеристики изменились;
- какие новые возможности появились;
- какие ограничения возникли;
- какие значения были пересчитаны.

Пользователь должен видеть последствия своего выбора до сохранения персонажа.

# Локализация

## Как отображать оригинальные названия?

При необходимости оригинальное название отображается рядом с переводом.

Например:

```
Fast-Talk (Быстрая речь)
```

или

```
Быстрая речь (Fast-Talk)
```

Формат определяется настройками пользователя.

## Когда показывать перевод?

По умолчанию отображается язык интерфейса.

Если перевод отсутствует, используется оригинальное название.

## Можно ли переключать язык отдельных элементов?

Да.

Пользователь может выбрать отображение:

- только перевода;
- только оригинального названия;
- обоих вариантов одновременно.

Эта настройка применяется независимо от языка интерфейса.
