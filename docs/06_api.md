# API

API предоставляет единый способ взаимодействия с ядром приложения независимо от типа клиента.

Клиентами могут быть:

- веб-интерфейс;
- настольное приложение;
- мобильное приложение;
- сторонние приложения;
- инструменты импорта и экспорта.

Ядро не должно зависеть от конкретного способа вызова API.

---

# Доступные сущности

Через API должны быть доступны все основные сущности системы:

- игровые системы;
- персонажи;
- контент;
- пользовательский контент;
- кампании;
- версии персонажей;
- настройки.

Конкретный набор может расширяться без нарушения обратной совместимости.

---

# Поддерживаемые операции

Для большинства сущностей поддерживаются стандартные операции:

- создание;
- получение;
- изменение;
- удаление;
- поиск;
- импорт;
- экспорт.

Дополнительно могут поддерживаться специализированные операции, например:

- пересчет персонажа;
- проверка корректности данных;
- применение пользовательского контента;
- получение истории изменений.

---

# Авторизация

Авторизация должна быть отделена от бизнес-логики.

На первом этапе допускается отсутствие авторизации.

В дальнейшем должны поддерживаться различные механизмы аутентификации, например:

- токены доступа;
- OAuth;
- внешние провайдеры.

Конкретный способ определяется реализацией приложения.

---

# Публичное API

Архитектура должна предусматривать возможность публикации API.

Публичный API позволит:

- создавать альтернативные клиенты;
- автоматизировать работу;
- интегрироваться с другими сервисами;
- разрабатывать сторонние расширения.

Наличие публичного API не является обязательным для первой версии проекта.

---

# Ограничения

API должно обеспечивать:

- проверку входных данных;
- контроль прав доступа;
- версионирование;
- стабильность контрактов.

При необходимости могут применяться дополнительные ограничения:

- ограничение частоты запросов;
- ограничение размера передаваемых данных;
- ограничение количества одновременно выполняемых операций.

---

# Принципы

API должно быть:

- независимым от пользовательского интерфейса;
- максимально стабильным;
- обратно совместимым при развитии проекта;
- расширяемым без изменения существующих контрактов.
