# Модель предметной области

## Фундаментальные сущности

---

## Игровая система

Игровая система — это описание правил, по которым создаются и развиваются персонажи.

### Обязательные составляющие

Игровая система должна содержать:

- уникальный идентификатор;
- название и версию;
- набор правил;
- определения типов игровых сущностей;
- набор доступного контента.

### Необязательные составляющие

Система может содержать:

- несколько редакций;
- локализации;
- официальные дополнения;
- пользовательские дополнения (Homebrew);
- настройки кампании;
- рекомендации по отображению интерфейса.

### Совместимость

Две системы считаются совместимыми, если:

- используют одинаковую модель данных;
- понимают один и тот же формат правил;
- имеют совместимые версии ядра.

Совместимость не означает идентичность контента.

---

## Персонаж

Персонаж — экземпляр игровой модели, созданный по правилам конкретной игровой системы.

### Базовые данные

Постоянно хранятся:

- идентификатор;
- принадлежность игровой системе;
- выбранный контент;
- значения, введённые пользователем;
- история изменений (при необходимости);
- пользовательские заметки.

### Вычисляемые данные

Могут вычисляться автоматически:

- итоговые характеристики;
- производные параметры;
- стоимость персонажа;
- ограничения;
- доступность способностей;
- модификаторы.

Эти данные не обязаны храниться, если могут быть восстановлены из исходных данных.

---

## Контент

Контент — любое описание игровых объектов, используемых системой.

Примеры контента:

- характеристики;
- навыки;
- преимущества;
- недостатки;
- способности;
- заклинания;
- расы;
- профессии;
- экипировка;
- эффекты;
- условия;
- шаблоны персонажей;
- любые другие игровые элементы.

Контент принадлежит конкретной игровой системе и интерпретируется только её правилами.

### Пользовательский контент

Пользователь может создавать собственный контент.

Такой контент:

- существует отдельно от официального;
- может расширять систему;
- может переопределять отдельные элементы (если это допускается системой);
- может экспортироваться и импортироваться.

---

## Связи

Допустимые связи:

- игровая система → контент;
- игровая система → правила;
- персонаж → игровая система;
- персонаж → контент;
- правила → контент;
- контент → контент.

### Циклические зависимости

Допускаются только те циклы, которые могут быть корректно разрешены ядром.

Например:

- способность ссылается на эффект;
- эффект ссылается на условие;
- условие проверяет наличие способности.

Не допускаются циклы, делающие невозможным вычисление состояния персонажа или приводящие к бесконечным вычислениям.

Ядро должно обнаруживать подобные зависимости и сообщать об ошибке.
